# 独立使用与协作

按当前任务选择主责 Skill。先看独立能力，再看需要跨职责时的交接方式；无需为了使用其中一个而装齐整个系列。

## 各自能完成什么

| Skill | 独立交付 | 何时交接 |
| --- | --- | --- |
| 7viow UX/UI Design | 设计方向、流程与状态、界面文案、规格或请求的设计产物，以及自检 | 需要专门评审时交给 UX Review |
| 7viow UX Review | 检查提供的界面/原型/截图/规格，输出问题、证据、修正和复验条件 | 用户要求落实修正时，交给 UX/UI Design 或现有实现者 |

两者各自携带完整方法、参考和模板，无需读取对方目录或安装其他 Skill。它们可使用宿主已经提供的能力；没有对应工具时，明确未完成的验证。

Design 附带的文案计数脚本只使用 Python 3 标准库。没有 Python 时，可用宿主的其他计算能力执行相同计数规则；规则本身仍适用。

## Design → Review → 修正

1. **Design 交付当前版本。** 连同用户目标、原材料、选定方向、Design System、允许改动及已验证结果提供给 Review。
2. **Review 返回一份问题清单。** 每项带稳定编号、证据、影响、最小修正和验收条件；保持只评审。
3. **获准的修正由 Design 或实现者完成。** 保留选定方向与未受影响的事实，回到维护源修改。复验沿用问题编号，记录解决、未解决及未验证项。

兄弟技能通过宿主实际可用的技能目录按名称或能力发现，不要求固定安装路径。用户指定了其他主设计或主评审方法时，沿用该选择。

只有 Design 时，照常交付设计与自检，并说明专门 Review 尚未执行。只有 Review 时，照常评审任何来源的产物并提供可移交的修正要求。同一执行者先设计再评审属于自评；独立评审需要另一执行者实际检查。

## 与 Talis 配合

[Talis](https://github.com/viowai/7viow-talis) 是 macOS 上整理和复用请求的桌面 App。复杂设计的条件分散、需要换工具接续，或准备进行多轮修改时，可以先用它整理请求，再复制给当前 AI 工具。需求已经清楚时直接设计或评审；一次按钮、错误提示修改也直接完成。

- **设计前**：带上用户任务、真实页面、设计规范和保留约束。Talis 中可用“界面设计：整理设计简报”模板。
- **设计交付后**：Design 会在有持续修改或交接需要时，附上已填充的请求，保留采用的方向、事实和允许改动范围。
- **评审后**：Review 会为需要跟进的问题附上复验请求，保留版本、问题编号、证据与检查范围。可以保存后用于下一版。

已经使用 Talis 时，直接保存这段请求作为个人模板；其他平台或不安装 Talis 时，使用同一份普通文本。每次只补新的材料和改动要求，无须重新填写已确认的决定。要安装时，按 [Talis 官方安装说明](https://github.com/viowai/7viow-talis/blob/main/docs/agent-install.md)操作。

例如，在设计交付后保存：

> 沿用所附报名表 v2 及其维护源，保留已选的单列布局和“保存草稿不提交报名”的行为。仅修复 UX-02 记录的保存失败恢复问题。修改源文件并重新生成，验证重试和返回表单；取消流程保持原样。

交给 Review 时，可以改为：

> 请对照所附 v2 评审及问题清单，复验下一版的 UX-02。触发保存失败并重试，确认提示与实际状态一致。保留单列布局，只评审；沿用原编号，分别报告解决、未解决和未验证。下一版文件准备好后另附。

这些是填写示例。实际请求应来自当前材料和已确认决定，尚未选择的方向继续保持待定。页面、原始材料和问题清单要通过接收工具另行提供；Talis 复制的是文字，不会传输附件、运行 Skill 或自动启动下一轮工作。

## 与 7viow 写作技能配合

以下是可选分工，不是安装依赖：

| 当前需要 | 可选能力 | UX Skill 继续负责 |
| --- | --- | --- |
| 探索品牌表达、内容方向或整体语气 | `7viow-writing-partner` | 用户任务、信息结构及表达进入界面的方式 |
| 修改已有长文、说明或文章 | `7viow-writing-editor` | 控件含义、状态文案、长度与交互一致性 |
| 将产品方案组织成演示叙事与逐页内容 | `7viow-deck-writing-editor` | 产品事实、设计决定与交互依据；幻灯片内容由 Deck 主责 |

普通按钮、错误提示和空状态文案由 Design 直接完成；不为几句界面文字强制经过写作技能。写作建议进入界面前，由 Design 核对必要条件、长度及实际行为，再由 Review 按需要验证。

## 交接时带什么

交接包含当前正文或产物、目标与受众、原始来源、已选决定、允许修改的范围、所需结果和未解决问题。可附现有评审与事实记录，复用已有内容即可。

一个任务保留一个内容主责负责整合。收到局部修改请求时，只处理授权部分；不重新展开已选方向，也不把多个技能输出拼成互相冲突的版本。实际调用与能力缺口如实说明。
