# Design and acceptance specification

## Review guide
Audience/task; requested artifact and fidelity; actual version/entrance; what to judge; feedback format; next action. Keep this guide beside product-facing content.

## Design intent
Mode: explore / develop / repair. Existing decisions; authorized change; source facts; creative method; Design System; assumptions that affect the result.

## Direction and source decision
For undecided core design, attach 2–3 inspectable alternatives, comparison and actual user/delegated selection using direction-options-template. For continuation/repair, cite the existing selection. Record DS discovery and the answer to any missing-source question.

## Screen/task contract
- User decision, entry, main action, completion:
- Real content objects, qualified identity, key relationships and representative content:
- Classification and finding/return path:
- Decision-critical / supporting / background / optional information and visual treatment:
- Layout, typography, spacing, color, surfaces, component anatomy and relevant motion:
- Responsive reading/action order and meaningful long/empty cases:

## Interaction and facts
For relevant controls: input → affected result → unit/time scope → recalculation/pending feedback.
For consequential state: starting state → trigger → result/evidence → persistence → recovery/focus.
For multi-audience work: audience → content/actions → entry/detail/search/source/download scope.
List actual Design System gaps and project-level supplements; keep project business rules in this artifact.

## Copy measurement
Per rewritten item: before/after, non-whitespace character counts, ratio, required meaning and any necessary exception. For new copy: declared numeric budget, actual count and result. Keep measurement in companion material, not product UI.

## Acceptance and handoff
For generated-artifact repairs: maintained source and affected element; generator/export path; affected views; regeneration command; rebuilt task evidence; unavailable source or output-only limitations. Omit this branch for directly maintained artifacts.

Task steps; expected result; actual result/evidence; tested artifact/version/environment; open defects or untested scope. For repairs, preserve finding IDs and unaffected behavior. Include the actual output and all resources required to use it. A small task can compress this template without generating empty sections.

## Conditional content and professional handoff

When needed, reference the existing content model, preferred labels/aliases, navigation/finding contract and actual research evidence; do not recreate them in parallel documents. Identify the actual design author, reviewer, integration owner and any specialist's assigned outcome. Preserve approved and rejected decisions and return actual artifacts/evidence. Same-execution self-review remains self-review; omit empty sections.
