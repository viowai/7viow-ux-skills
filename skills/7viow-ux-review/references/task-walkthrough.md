# Task walkthroughs

Use only the branches present in the artifact. Select representative real content, including a long item or an awkward state when it changes task behavior. Record environment and state, not an arbitrary total score.

## Comparison

Choose distinct objects. Can the user compare the same meaningful dimension without remembering an entire preceding item? Preserve object identity and non-comparable conditions. At the actual narrow viewport, compare text, controls, and selected state; no overflow alone does not establish comparability. Do not fix every mobile comparison with the same layout.

## Data controls

Change an input and identify every result it should affect. Verify scope, unit, time range, current input, and whether recalculation is automatic or pending. Compare the readout with the supplied source or formula when available; do not invent new calculations to conceal missing inputs. Different monthly/cumulative outputs can coexist if their boundaries are unmistakable.

## Search and evidence

Search by content a user would know. Examine context in the results, open the matching object/paragraph, then return. Preserve query, filters, selection, and position when that is the task expectation. Test empty results and a reachable missing target. IDs should lead to a recognizable object, not to an unrelated record sharing the same short ID.

## Editing and return

Enter a draft, close/reopen, navigate back, and reload according to the product's stated persistence contract. Test saving and exporting separately; a downloaded file is not proof of source synchronization. Check restoration of the affected object, selection, scroll position, and focus. Use isolated test data; never overwrite genuine notes to demonstrate recovery.

## Keyboard, width, and height

Trace focus through menus and dialogs, including closing and return. Hidden controls should not capture unreachable focus. Evaluate realistic desktop/narrow widths, short height when a fixed control/modal is present, and long content. Inspect usable reading width, text size, labels, overlap, and reachable controls as well as page overflow.

## Status and audiences

Follow the evidence that makes a state true. Planning dates are not confirmed commitments unless the project defines them that way. Separate unknown, empty, blocked, unavailable, and failed according to their actual causes.

When audiences differ, compare the visible page and its search, detail, source, and download paths with the declared content scope. Visual filtering is not an access-control guarantee. Report a demonstrated mismatch; do not turn a UX review into an unsolicited security audit.

## Source and regeneration

Use when a repair claims to persist through a build, export, data refresh, or repeated rendering. Trace the affected element through the supplied maintained source and its generator to the inspected output. Request or inspect existing regeneration evidence; when authorized, reproduce the existing build in a disposable copy without editing product source. Do not turn a review-only request into implementation.

Check the regenerated artifact's user task and a second affected record/state where hardcoding is reachable. Include relevant audience/search/full-text/export variants that share the source. An edited export, a source diff, and a successful build each prove different things; none alone closes the visible task.

If the source or runtime is missing, report what was observed and leave persistence unverified. A declared one-off output patch may meet a one-off request; it is not evidence that the maintained product is repaired. Directly maintained HTML/native objects need no fabricated generation step. Recommend the correct owning layer without changing it during Review.

## Honest case reporting

Record task, initial state, expected result, actual result, evidence, and cleanup. Label expert walkthrough, automated check, and participant study accurately. Reconstructed examples are not direct production observations; self-reported checks need inspection before being accepted as evidence.
